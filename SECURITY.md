# Безопасность

## Как сообщить об уязвимости

Напишите **[@ipostatos](https://t.me/ipostatos)** в Telegram. Это единственный
канал — GitHub Issues для уязвимостей **не используйте**: они публичные.

Что помогает разобраться быстрее:

- что именно происходит и как это воспроизвести;
- какой компонент затронут — бот, Mini App или API синхронизации;
- чем это грозит пользователю (доступ к чужому прогрессу, утечка данных, отказ
  в обслуживании).

**Пожалуйста, не выкладывайте находку публично, пока она не закрыта.**

Проект ведёт один человек в свободное время. Ориентир: ответ в течение недели,
исправление критичного — как только оно будет готово и проверено. Наград за
находки нет; благодарность и упоминание в CHANGELOG — по вашему желанию.

## Что считается уязвимостью

- обход проверки Telegram `initData` (HMAC) или доступ к данным чужого
  пользователя;
- SQL-инъекция, path traversal, XSS в Mini App;
- утечка `BOT_TOKEN` или содержимого базы синхронизации;
- отказ в обслуживании, достижимый одним запросом.

## Что уязвимостью не считается

- отсутствие rate limit на неаутентифицированных запросах (известно, закрывается
  на уровне веб-сервера);
- сам факт публичности репозитория и доступности учебного контента —
  это лицензионный вопрос, см. [`LICENSE`](LICENSE);
- отчёты автоматических сканеров без подтверждённого сценария эксплуатации.

## Что уже сделано

Не список обещаний, а то, что стоит в коде и проверяется на каждый push:

- подлинность пользователя — строго по Telegram `initData` (HMAC,
  `compare_digest`); `user_id` берётся **только** из проверенной подписи и
  никогда из тела запроса;
- все SQL-запросы параметризованы; слияние состояния идёт в одной транзакции
  (`BEGIN IMMEDIATE`) — без гонки потерянного обновления;
- лимит размера тела запроса проверяется **до** буферизации (ранний `413`);
- потолки на объём состояния — подписанный клиент не может залить
  неограниченный мусор в общий диск;
- сервисы работают от непривилегированной учётной записи; systemd-юниты
  захардены (`ProtectSystem=strict`, узкие `ReadWritePaths`, `NoNewPrivileges`);
  API слушает только localhost;
- деплой не выполняет код и `pip` от root;
- CI на каждый push: поиск утечённых токенов, запрет на попадание в git
  `.env`, баз и бэкапов, запрет разовых `pip install` в деплой-скриптах;
- бэкапы БД лежат **вне** рабочего дерева git, с правами `700/600`.

## Данные пользователей

Что именно хранится и зачем — в [`PRIVACY.md`](PRIVACY.md) (в боте — команда
`/privacy`). Коротко: Telegram `user_id`, прогресс обучения и история
прохождений. Ни сообщений, ни контактов, ни платёжных данных проект не хранит.
